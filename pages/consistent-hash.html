💠 一致性哈希

把数据分散到多台服务器时，普通做法是 hash(key) % N。 但只要增删一台机器，N 变了，几乎所有 key 都要重新搬家——缓存瞬间全失效。 一致性哈希把哈希空间弯成一个环来解决这个问题。

服务器 虚拟节点 key 数量 数据源：本地

核心思路：把哈希空间弯成环

① 哈希值范围是 0 ~ 2³²-1，把它首尾相连成一个圆环

② 每台服务器按 hash(服务器名) 放到环上

③ 每个 key 也哈希到环上，顺时针找到的第一台服务器就是它的归属

这样增删一台机器，只影响环上相邻的一小段区间， 其余 key 完全不动——这就是它"一致性"的含义。

虚拟节点：让负载更均匀

只用 4 台服务器直接放到环上，位置可能挤在一起，导致负载倾斜。

解法：每台物理机映射成 N 个虚拟节点散布在环上， 各自的区间被"打散"，负载就均衡了。

实测对比：移除一台服务器会迁移多少数据？

这就是为什么 Redis Cluster、Cassandra、Memcached 客户端 都采用一致性哈希——它把"扩容导致缓存雪崩"的风险降到了最低。
